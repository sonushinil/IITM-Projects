7.7: SVM vs Random Forest - Demo 
While both are powerful, they are conceptually very different. SVM tries to find the optimal decision 
boundary by maximising margins between classes. Random forest, on the other hand, works through 
a collection of decision trees using ensemble learning to improve stability and accuracy. Our goal is 
to develop an intuitive understanding of when and why to use each and what their outputs look like 
in practise. Now let's walk through the key differences between support vector machines and 
random forests, two powerful but fundamentally different classification algorithms. This comparison 
will help you decide when to use which based on your data and objectives. 
Let's start with the basic philosophy approach. SVM works by finding the hyperplane that best 
separates the classes with the maximum possible margin. Think of it as drawing a very confident 
boundary between classes. Random forest, on the other hand, takes an ensemble approach. It builds 
multiple decision trees and combines their outputs, usually through majority voting. So while SVM 
focusses on margins, random forest relies on consensus. 
Feature scaling needed. SVM is a distance-based algorithm, which means it's sensitive to the scale of 
your input features. You must normalise or standardise your data before feeding it to an SVM. 
Random forest doesn't care about the scale of features. It splits the data based on thresholds, not 
distances. So it works just fine without any scaling. This makes random forest easier to plug into raw 
dataset. 
What if data is nonlinear? SVM can handle nonlinear relationships using something called the kernel 
trick, which projects your data into higher dimensions where a linear separator can be found. 
Random forest, thanks to the nature of decision trees, inherently captures nonlinear patterns. 
Without needing special tricks, it splits the data in a hierarchical way that naturally adapts to 
complex structures. 
Interpretability. How interpretable are the results? SVM, especially with nonlinear kernels, becomes 
a black box. It's hard to explain why a particular prediction was made. Random forest offers 
moderate interpretability. You can extract feature importances and even visualise individual decision 
trees. But it's not as interpretable as simple linear model. It's much more explainable than SVM.

Overfitting risk. SVM can overfit easily if your dataset is small or noisy, particularly when using 
complex kernels. Random forest reduces the risk of overfitting by averaging predictions from 
multiple trees. This ensemble approach, known as bagging, makes it more robust to noise and 
outliers. 
Training time. Lastly, the training time, SVM tends to scale poorly with data size. As the number of 
data points grows, training time increases significantly. Random forest scales better, especially for 
small to medium datasets. It can also be parallelised easily, which makes it faster in practise. So in 
summary, SVM is precise and powerful for well-prepared, clean datasets where class boundaries are 
clear. Random forest is robust, flexible, and forgiving. A go-to model for messy real-world data. Keep 
these differences in mind as we move on to the practical demo and compare both models in action. 
When to use what? So when we should use SVM and when should you go for random forest? If 
you're working with a clean dataset and you expect well-separated classes, SVM can work very well, 
especially in smaller datasets. But if you are in a typical real-world scenario where data might be 
messy or mix of types, random forest becomes a more practical option. Especially if you are looking 
for quick wins and don't want to fuss too much about feature scaling.

7.8: Hyperparameter Tuning Random Forest with GridSearchCV - Demo 
Before we train any machine learning model, we need to decide on a few configuration settings. 
These are called hyperparameters. Unlike model parameters that are learned from the data during 
training, like coefficients in linear regression, hyperparameters are set before the training process 
begins. They determine how the model will learn. For example, in random forest, we decide 
beforehand how many trees to include, how deep those trees can grow, and what criteria to use 
when splitting nodes. Tuning these values has a big impact on performance. The right 
hyperparameter configuration can dramatically improve accuracy, reduce overfitting, and make the 
model generalise better. In layman language, if I have to explain what hyperparameters are, think of 
them as certain parameters in the model which are not learned from the data, but they impact your 
model performance. Tuning them for the right value will improve your model performance. On the 
other hand, if you move in the wrong direction, it might actually deteriorate your model 
performance as well. 
Hyperparameters in random forest. Let's take a closer look at some of the most commonly tuned 
hyperparameters in a random forest classifier. We have many of them, some of which are 
mentioned here. n_estimators: This controls the number of trees in the forest. More trees generally 
give better results but also increase training time, so you have to strike a balance. Start with some 
decent number for the n_estimators, see how the model is performing, then gradually increase it. 
max_depth: This sets the maximum depth for each tree. Shallow trees may underfit, while very deep 
ones tend to overfit. min_samples_split: This is the minimum number of samples required to split an 
internal node. Increasing this value makes the model more conservative. min_samples_leaf: This 
sets the minimum number of samples required to be at a leaf node. It helps reduce overfitting by 
smoothing the trees. max_features: This defines how many features to consider at each split. You 
can use square root or log base 2 to reduce variance. bootstrap: This controls whether to use 
bootstrap samples when building trees. When set to false, it uses the whole dataset for each tree. All 
of these impact how flexible, generalisable or robust the final model becomes. 
So why go through the trouble of tuning? By selecting the right hyperparameter values, we can 
unlock the true potential of a model. Good tuning helps us avoid overfitting, where the model 
memorises the training data, or underfitting, where it fails to learn patterns properly. It also ensures 
optimal performance on validation and test datasets, leading to better accuracy in real-world

predictions. Lastly, hyperparameter tuning brings structure and automation to experimentation, 
making it easier to test different ideas systematically. 
Now let's talk about GridSearchCV, the tool we will use for tuning. GridSearchCV stands for grid 
search with cross-validation. It takes a dictionary of hyperparameters and performs an exhaustive 
search over all possible combinations. For each combination, it trains the model multiple times using 
cross-validation and evaluates performance. In the end, it tells us which combination worked best, 
along with the corresponding performance score. It's thorough, systematic, and one of the most 
reliable ways to tune models when the dataset is not too large. GridSearchCV will help you to find 
the best set of hyperparameters from the given set of values. So if you provide five values for a 
hyperparameter, GridSearch will evaluate each one of them and tell you which is the best value in 
terms of getting a better model. 
One important aspect to understand is that GridSearch does not search for the best parameter 
possible on its own. It simply tells you among the given set of values which one is better. So if you 
are providing five values, it evaluates each one of them and tells you among those five which one is 
the best. It does not look for any other value than what you have provided. If you have not provided 
the right value, then GridSearchCV will not go and search on its own.
